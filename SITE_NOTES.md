# Site Notes

This repository is a GitHub Pages / Jekyll personal website using the
Minimal Mistakes remote theme. The repo is intentionally small: most layout,
HTML, CSS, search UI, author sidebar, archive pages, and responsive behavior
come from the theme, while this repo provides configuration, content, nav data,
and images.

## Current Architecture

- `_config.yml` is the main Jekyll configuration file. It defines site metadata,
  the GitHub repository, Markdown engine, permalink style, pagination, included
  folders, plugins, author/sidebar data, footer links, and default layouts for
  posts and pages.
- `Gemfile` declares the Ruby/Jekyll dependencies used for local development.
  The main dependency is `github-pages`, which pins the gem versions supported
  by GitHub Pages. The file also lists several Jekyll plugins.
- `index.md` is the homepage entry point. It has YAML front matter and
  uses `layout: home`, which comes from Minimal Mistakes. The homepage content
  is generated by the theme from the posts collection.
- `_pages/` contains standalone pages that are included because `_config.yml`
  has `include: [_pages]`. These pages define their public URLs with
  `permalink`.
- `_posts/` contains dated blog/research notes. Jekyll turns files named
  `YYYY-MM-DD-title.md` into posts.
- `_data/navigation.yml` defines the top navigation menu consumed by Minimal
  Mistakes.
- `assets/images/` contains images used by posts and the author avatar/logo.
- `assets/proto/` contains source/prototype material for the recombination post,
  including an R Markdown file and generated Markdown. These are not part of the
  normal Jekyll content flow unless explicitly linked.
- `_site/` is the generated static site output when Jekyll builds locally. It is
  ignored by git and should not be edited by hand.

There are currently no local `_layouts/`, `_includes/`, `_sass/`, or
`collections` directories. Those pieces are supplied by the remote theme.

## How Jekyll Builds This Site

1. Jekyll reads `_config.yml`.
2. It loads the Minimal Mistakes remote theme from `mmistakes/minimal-mistakes`.
3. It reads pages in the root and in `_pages/`.
4. It reads posts in `_posts/`.
5. It applies defaults from `_config.yml`, so posts automatically use the
   theme's `single` layout unless a post says otherwise.
6. It reads `_data/navigation.yml`; Minimal Mistakes uses `main:` for the masthead
   navigation.
7. It copies static assets such as images.
8. It writes the generated static site to `_site/`.

## Deployment

This is a user/organization GitHub Pages repository named
`nosimpler.github.io`. For this repository type, GitHub Pages normally deploys
the default branch directly to:

`https://nosimpler.github.io/`

The usual deployment process is:

```sh
git status
git add <changed files>
git commit -m "Describe the site update"
git push
```

GitHub Pages then runs Jekyll remotely and publishes the result. Do not commit
`_site/`, `.sass-cache/`, `.jekyll-metadata`, or local Bundler output.

## Local Development

### Dev Container

This repo includes a VS Code / GitHub Codespaces devcontainer in
`.devcontainer/`. It uses Ruby 3.2 on Debian Bookworm, plus native build tools
needed by common Jekyll gems.

In VS Code:

1. Install the Dev Containers extension.
2. Run "Dev Containers: Reopen in Container".
3. Wait for `bundle install` to finish.
4. Start the site:

   ```sh
   bundle exec jekyll serve --host 0.0.0.0 --livereload
   ```

Then open the forwarded port for:

`http://127.0.0.1:4000/`

The same container should also work in GitHub Codespaces.

### Native Ruby

Recommended modern setup:

```sh
ruby -v
gem install bundler
bundle install
bundle exec jekyll serve
```

Then open:

`http://127.0.0.1:4000/`

Useful commands:

```sh
bundle exec jekyll build
bundle exec jekyll serve --livereload
bundle exec jekyll clean
```

If using the system Ruby on macOS, avoid installing gems globally. Prefer a Ruby
version manager such as `rbenv`, `chruby`, `asdf`, or Homebrew Ruby, then run
`bundle install` inside the project.

Current machine note from May 28, 2026: Apple Ruby 2.6.10 and Bundler 1.17.2
were present. A plain `bundle install` tried to write to `/Library/Ruby`, and
`bundle install --path /private/tmp/nosimpler-bundle` reached RubyGems but
failed dependency resolution because `ffi-1.17.4-x86_64-darwin` requires Ruby
3.x. The practical fix is to install and select a modern Ruby, then rerun
`bundle install`.

## Troubleshooting

- `bundler: command not found: jekyll`
  - Dependencies are not installed for this repo. Run `bundle install`.
- Permission errors involving `/Library/Ruby`
  - You are using macOS system Ruby. Use a user-managed Ruby instead of `sudo`.
- A gem requires Ruby 3.x
  - Install a newer Ruby and rerun Bundler.
- `No GitHub API authentication could be found`
  - Usually a local development warning from GitHub metadata. The site may still
    build. For full metadata locally, set a GitHub token, but this is not
    normally required for simple content editing.
- Changes to `_config.yml` do not appear
  - Restart `bundle exec jekyll serve`; config changes are not always reloaded.
- Broken images in posts
  - Prefer root-relative URLs such as `/assets/images/logo.png` over
    `../assets/images/...`, especially when permalinks change.
- Page exists locally but has no output
  - Make sure the file has YAML front matter at the top and either lives in a
    normal Jekyll location or is included by `_config.yml`.

## Editing The Homepage

The homepage is `index.md`:

```yaml
---
layout: home
author_profile: true
---
```

The actual homepage layout is supplied by Minimal Mistakes. It lists recent
posts and shows the author profile because `author_profile: true`.

To add custom homepage copy, add Markdown or HTML below the front matter in
`index.md`. To make a heavily customized homepage, create or override a layout,
but that is a larger maintenance step.

## Adding A Page

Create a Markdown file in `_pages/`, for example `_pages/projects.md`:

```markdown
---
title: "Projects"
permalink: /projects/
---

Write page content here.
```

The page will use `layout: single` and show the author profile because of the
defaults in `_config.yml`.

To add it to the top nav, edit `_data/navigation.yml`:

```yaml
main:
  - title: "Projects"
    url: /projects/
```

## Adding A Blog Or Research Note

Create a Markdown file in `_posts/` using this naming pattern:

`YYYY-MM-DD-short-title.md`

Example:

```markdown
---
title: "A Clear Post Title"
date: 2026-05-28
categories:
  - research
tags:
  - computational-neuroscience
  - math
---

Write the post here.
```

The post URL is controlled by `permalink: /:categories/:title/`. If no category
is set, the URL will be based mostly on the title. Categories and tags also feed
the archive pages.

## Adding A PDF CV

1. Put the PDF somewhere stable, for example:

   `assets/pdf/cv.pdf`

2. Link it from `_pages/about.md` or a new CV page:

   ```markdown
   [Download CV](/assets/pdf/cv.pdf)
   ```

3. If you want a top-level nav item, add this to `_data/navigation.yml`:

   ```yaml
   - title: "CV"
     url: /assets/pdf/cv.pdf
   ```

Create `assets/pdf/` if it does not already exist.

## Updating Navigation

Edit `_data/navigation.yml`. The current structure is:

```yaml
main:
  - title: "Posts"
    url: /posts/
  - title: "Categories"
    url: /categories/
  - title: "Tags"
    url: /tags/
  - title: "About"
    url: /about/
```

Minimal Mistakes reads the `main` list for the masthead menu. The URL should
match a page's `permalink` or an asset path.

## Project-Specific Oddities

- The README is still the upstream Minimal Mistakes starter README, not a
  project-specific README.
- The About page currently contains placeholder lorem ipsum text.
- `assets/proto/` contains source/prototype material for the existing post. It
  is useful historically, but it is separate from the published `_posts/`
  Markdown file.
- The existing post uses relative image paths like `../assets/images/...`.
  Root-relative paths like `/assets/images/...` are usually less fragile.
- `jekyll-algolia` appears in the Gemfile but not in `_config.yml`'s `plugins`
  list. It is not currently part of the configured build.
- Comments are enabled by default for posts, but no comment provider is
  configured in `_config.yml`, so this may not produce visible comments.
- `timezone:` is blank.
- There is no `Gemfile.lock`, and `.gitignore` ignores it. That keeps the repo
  loose, but local installs may drift over time.

## Minimal Modernization Plan

Keep Jekyll, GitHub Pages, Markdown content, and Minimal Mistakes. Do not add
React, a database, or a CMS.

Recommended small changes:

1. Replace placeholder About content with a concise professional bio.
2. Add dedicated pages for Research, Projects, Writing, and CV.
3. Simplify navigation to About, Research, Projects, Writing, CV.
4. Add categories/tags consistently to posts.
5. Move generated/source material under a clearer folder name, such as
   `assets/source/` or `notebooks/`, if you want to keep it in the repo.
6. Use root-relative asset links in posts and pages.
7. Add `assets/pdf/cv.pdf` and link it from About and nav.
8. Decide whether to keep comments. If not, set `comments: false` in post
   defaults.
9. Remove unused `jekyll-algolia` from the Gemfile unless search indexing is
   actually desired.
10. Consider committing a `Gemfile.lock` for reproducible local builds, or keep
    ignoring it if strict GitHub Pages parity matters more than local stability.

Estimated difficulty: low to medium. Content cleanup and navigation are low
difficulty. Reworking the homepage within the theme is low. Overriding layouts
or deeply changing the theme is medium and should wait until the content model
is clear.

Proposed site structure:

```text
/
  index.html                  # homepage / recent writing
  _pages/
    about.md                  # bio, interests, contact
    research.md               # computational neuroscience and math research
    projects.md               # software/projects portfolio

    YYYY-MM-DD-title.md       # research notes / essays
```
